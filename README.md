# KazStyle

[![KazStyle CI](https://github.com/zzmaga/disser/actions/workflows/ci.yml/badge.svg)](https://github.com/zzmaga/disser/actions/workflows/ci.yml)

KazStyle определяет функциональный стиль казахского текста: официально-деловой,
научный, публицистический, художественный или разговорный. Проект объединяет
подготовку корпуса, сравнение моделей и локальный сайт для проверки текстов.
Предсказания выполняют обученные модели на компьютере; внешний ИИ API не используется.

Проект развивается в рамках магистерской диссертации.
[Текущее состояние, результаты и ограничения](docs/PROJECT.md).

## Быстрый запуск примера очистки

Этот небольшой модуль можно запустить сразу после скачивания репозитория,
без GPU, корпуса и весов моделей. Он использует очиститель из основного проекта:
удаляет ссылки и HTML, исключает пустые строки и точные повторы после очистки.
Казахские буквы, имена и даты сохраняются.

**Это демонстрация обработки текста, а не классификатор стилей.** Пять искусственных
примеров лежат в [examples/cleaning_input.jsonl](examples/cleaning_input.jsonl).
Они не используются как обучающий корпус или исследовательский тест.

Нужен Python 3.12 или новее. В GitHub Actions используется Python 3.12.

Windows / PowerShell:

```powershell
git clone https://github.com/zzmaga/disser.git
cd disser
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r configs/requirements-ci.txt
.venv/Scripts/python.exe -m kazstyle.demo --out-dir build/demo
.venv/Scripts/python.exe -m pytest tests/test_demo.py tests/test_api_contract.py
```

Linux:

```bash
git clone https://github.com/zzmaga/disser.git
cd disser
python3 -m venv .venv
.venv/bin/python -m pip install -r configs/requirements-ci.txt
.venv/bin/python -m kazstyle.demo --out-dir build/demo
.venv/bin/python -m pytest tests/test_demo.py tests/test_api_contract.py
```

Откройте `build/demo/report.html` в браузере. Ожидаемый результат: **5 входных строк,
3 сохранены, 2 исключены** — повтор и строка только со ссылкой. Рядом сохраняются
`cleaned.jsonl` и `summary.json` с причинами исключения и контрольной суммой входа.

Для своего UTF-8 JSONL передайте `--input путь/к/файлу.jsonl`. Каждая строка должна
содержать только поля `id` и `text`: строки, причём `id` непустой и уникальный.
Для повторного запуска выберите новый каталог, например `--out-dir build/demo-2`:
программа не перезаписывает существующий результат.

## GitHub Actions: автоматические проверки

[Конфигурация CI](.github/workflows/ci.yml) ·
[Запуски и их результаты](https://github.com/zzmaga/disser/actions/workflows/ci.yml)

Workflow запускается при push в `main`/`codex/**`, pull request в `main`, а также вручную.
Проверки проходят независимо на Ubuntu и Windows с Python 3.12:

1. Устанавливаются небольшие зависимости с фиксированными версиями.
2. Pytest проверяет очистку, экспорт, группировку, сборщики, HTTP API и отчёты.
3. Запускается пример очистки и создаётся HTML-отчёт.
4. Журналы тестов и результат примера сохраняются в downloadable artifacts на 14 дней.

Ошибки тестов и сбои обнаружения завершают проверку неуспешно.
Число выполненных и пропущенных тестов видно в журнале и JUnit XML.
Эта проверка подтверждает работу кода; она не оценивает точность классификации
и не переобучает модели. Полные проверки с локальными весами запускаются отдельно.

Для нового запуска владелец репозитория может нажать
**Run workflow → main → Run workflow** на странице workflow.

После успешных тестов выполняется Docker/Kubernetes job: тесты внутри образа,
сборка runtime, HTTP-проверка контейнера, загрузка того же образа в отдельный kind
кластер, Deployment/Service и повторная HTTP-проверка. Это автоматическое
развёртывание в одноразовую тестовую среду; публичный сайт и новые веса не публикуются.
Доказательства сохраняются как `kazstyle-devops-evidence` на 30 дней.

### Docker и Kubernetes: подготовка корпуса

Контейнер использует настоящие `clean_text` и `demo.prepare` из KazStyle.
Он очищает HTML/ссылки и исключает точные повторы; классификация и обучение сюда
не входят. В образ не попадают исходный корпус, веса, `.env` и история Git.

```powershell
docker build --target test .
docker compose up --build -d
.venv/Scripts/python.exe -X utf8 deploy/smoke.py http://127.0.0.1:8085
```

Откройте http://localhost:8085/docs и `POST /api/prepare`: до 20 записей
`{"id":"sample","text":"Қазақ тілі. https://example.org"}` в поле `records`.
Остановка: `docker compose down`. Основной сайт на 8765 работает отдельно.

Для Kubernetes нужен собственный тестовый kind-кластер; не используйте случайный
текущий context. [Манифест](deploy/kubernetes/preparation.yaml) ограничивает RAM/CPU,
использует non-root, read-only filesystem, readiness/liveness probes.

```sh
docker build --target runtime -t kazstyle-preparation:ci .
kind create cluster --name kazstyle-ci
kind load docker-image kazstyle-preparation:ci --name kazstyle-ci
kubectl --context kind-kazstyle-ci apply -f deploy/kubernetes/preparation.yaml
kubectl --context kind-kazstyle-ci -n kazstyle-demo rollout status deployment/preparation --timeout=120s
kubectl --context kind-kazstyle-ci -n kazstyle-demo port-forward service/preparation 8086:80
```

В другом терминале: `python deploy/smoke.py http://127.0.0.1:8086`.
После демонстрации удалить только созданный тестовый кластер:
`kind delete cluster --name kazstyle-ci`. Docker Hub и платное облако не нужны.

Ревизия 19 октября переводит CI на pytest: 150 проверок локально прошли без ошибок
и пропусков. Набор не требует корпуса, весов и PyTorch/Transformers. Результат
GitHub Actions нужно смотреть для конкретного коммита во вкладке Actions.
Для полного набора проверок данных на чистой копии:

```powershell
.venv/Scripts/python.exe -m pip install -r configs/requirements-data-ci.txt
.venv/Scripts/python.exe -m pytest --junitxml=build/ci-tests.xml
```

Состав переносимых проверок задаётся в `pytest.ini`; отдельного самописного runner нет.

## Полный сайт с обученными моделями

На подготовленном компьютере запустите `start_site.cmd` и откройте
**http://127.0.0.1:8765**. Вставьте казахский текст и нажмите «Сравнить все».
Сайт показывает ответы шести вариантов и прочитанный фрагмент длинного текста.
Сервер использует **FastAPI + Pydantic + Uvicorn**. Схема API доступна локально
по `/openapi.json`; страница и предсказания не требуют внешних сервисов.

Ручной запуск из корня проекта:

```powershell
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe manage.py serve
```

Для этого нужны локальный корпус `data/processed/text_only_v4_shared/`, токенизаторы
и четыре каталога весов, указанные в [configs/deployment.json](configs/deployment.json).
Один каталог классических моделей содержит три классификатора.
**Корпус и веса не входят в Git: одного клонирования и установки зависимостей
для запуска полного сайта недостаточно.** Команды работы с данными и моделями:
[WORKFLOW.md](docs/WORKFLOW.md); окружение для обучения: [GPU.md](docs/GPU.md).

## Какие модели сравниваются

| Вариант | Как работает |
| --- | --- |
| Word TF-IDF + Logistic Regression | Признаки слов и логистическая регрессия |
| Word TF-IDF + Linear SVM | Признаки слов и линейный метод опорных векторов |
| Character TF-IDF + Linear SVM | Признаки последовательностей символов и линейный SVM |
| mBERT | Дообученная многоязычная нейросеть |
| Kaz-RoBERTa last | Дообученная казахская нейросеть, представление последнего слоя |
| Kaz-RoBERTa concat4 | Та же базовая нейросеть, объединение последних четырёх слоёв |

TF-IDF преобразует текст в числовые признаки; LR или SVM выполняет классификацию.
Поэтому «TF-IDF + SVM» — один законченный вариант модели.

Основной сайт использует профиль **v4**, построенный на 610 текстах.
Расширенное сравнение **v6** завершено на 1 265 текстах, по 253 на стиль,
с тремя seed: 42, 43 и 44. У сравниваемых моделей одинаковые входные тексты
и разбиение; выбор модели выполняется по validation.

V6 пока не заменяет основной сайт: обнаружена ошибка на школьном заявлении.
Метки корпуса предварительные, а внутренний test уже изучался при разработке.
Высокие внутренние метрики не гарантируют качество на произвольном тексте.
Подтверждённые числа, ограничения и оставшиеся задачи — в [паспорте проекта](docs/PROJECT.md).

## Где находится корпус

Текущая цель — увеличить четыре малых класса до 11 425 документов каждый, наравне
с публицистикой версии 10 октября. Новую публицистику не собираем; 2 000/стиль —
промежуточный этап. Путь завершённого
корпуса и список ещё не объединённых партий находятся в
[реестре корпуса](configs/corpus_registry.json). Новые кандидаты не прибавляются
к проверенному объёму автоматически. Реестр корпуса отделён от профиля моделей сайта.

Единая версия для следующей итерации — локально в
`data/cleaned/unified_corpus_20261018b/`. `corpus.html` показывает состав и ссылки на файлы;
`corpus.csv` содержит только `text,label`, а `by_style/` — такие же CSV по стилям.
Источники, ID, группы и происхождение меток лежат в `metadata.jsonl`.
Сомнительные и исключённые записи вынесены отдельно. Готовая сборка имеет `COMPLETE.json`.
Версия 18b от 18.10.2026 содержит 29 585 документов после отбора; 4 897 записей оставлены на разбор,
336 исключены с объяснениями. Разговорный класс достиг 2 053 документов после полного
AI-assisted просмотра 888 новых кандидатов (810 приняты по стилю). Из сохранённых HTML восстановлены 1 827 пропущенных слов
в 126 сказках; юбилейная заметка исключена из научного класса. Метки предварительные.
Содержательная проверка ассистентом обозначается AI-assisted curation, без заявления
о человеческом экспертном gold. На этой версии новые модели ещё не обучались.

Это предварительный корпус документов, ещё не новое обучение или независимый test.
Все пригодные записи сохраняются без прежнего лимита 1000 на стиль; баланс классов
нужно учитывать при подготовке обучающей выборки. Порядок сборки и проверки:
[WORKFLOW.md](docs/WORKFLOW.md).

## Структура проекта

| Путь | Назначение |
| --- | --- |
| `kazstyle/data/` | Сбор, очистка, версии корпуса и проверка разбиения |

| `configs/` | Зависимости, источники, планы экспериментов и профили сайта |
| `docs/` | Состояние, команды, архитектура и инструкции GPU |
| `data/`, `artifacts/`, `models/` | Локальные данные и веса, исключённые из Git |
| `reports/` | Локальные результаты и компактные числовые доказательства прежних экспериментов |

## Полные локальные тесты

```powershell
.venv/Scripts/python.exe -m pip install -r configs/requirements-data-ci.txt
.venv/Scripts/python.exe -m pytest tests
```

Полный набор включает проверки моделей и HTTP и требует локальных ресурсов проекта.
Для чистой копии репозитория используйте `python -m pytest` после установки
`configs/requirements-data-ci.txt`; по умолчанию выбирается переносимый набор.
Исследовательские эксперименты и показатели качества хранятся отдельно от журналов CI.

## Лицензия и задачи

Собственный код и сопроводительная документация KazStyle распространяются по
[MIT License](LICENSE). Разрешено использовать и изменять код с сохранением
уведомления об авторстве и текста лицензии. Сторонние библиотеки, исходные тексты
корпуса и предобученные модели сохраняют собственные условия использования;
MIT-лицензия проекта не предоставляет дополнительных прав на эти материалы.

Текущие задачи ведутся в [GitHub Issues](https://github.com/zzmaga/disser/issues):

- [#1 — регрессия на школьном заявлении и деловые жанры](https://github.com/zzmaga/disser/issues/1).
- [#2 — независимая человеческая проверка меток](https://github.com/zzmaga/disser/issues/2).
- [#3 — установка полного сайта на чистом компьютере](https://github.com/zzmaga/disser/issues/3).

В каждой задаче указаны проблема, действия и критерий завершения. Открытая задача
означает оставшуюся работу; само создание Issue не означает её выполнение.
Issue #2 описывает вариант независимой проверки людьми. 18 октября пользователь
выбрал AI-assisted curation; это отражено в `docs/PROJECT.md` и не выдаётся за
выполнение человеческой разметки из старой задачи.
