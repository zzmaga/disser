# Устройство проекта

`manage.py` и `python -m kazstyle` запускают одинаковые команды. Список: `python manage.py --help`.
Параметры команды: `python manage.py train-transformer --help`.

| Папка | Назначение |
| --- | --- |
| `kazstyle/api/` | Локальный HTTP-сервер и маршруты сайта |
| `kazstyle/inference/` | Загрузка сохранённых весов, предсказания, CLI |
| `kazstyle/models/` | Архитектура нейросети |
| `kazstyle/training/` | Обучение классических моделей и трансформера |
| `kazstyle/data/` | Чтение CSV, очистка, фрагменты, split, аудит, импорт кандидатов |
| `kazstyle/evaluation/` | Метрики, отчёты, сравнение и проверка весов |
| `frontend/` | HTML, CSS и JavaScript интерфейса |
| `configs/` | Снимок версий установленного окружения |
| `data/` | Исходные CSV; `processed/` — версии корпуса; `external/` — кандидаты |
| `artifacts/` | Отдельная папка каждого запуска обучения и его веса |
| `reports/` | Сгенерированные отчёты |
| `docs/research/` | Материалы и выводы исследования с датой |
| `tests/` | Проверки данных и локального предсказания |
| `archive/` | Старый код, эксперименты и временные материалы |

Поток запроса: браузер → `/api/classify` → `InferenceService` → подготовка фрагмента → локальная модель → стиль.
CLI `predict` использует тот же сервис. Внешний ИИ API не вызывается.
`kazstyle/settings.py` задаёт корень проекта; пути по умолчанию не зависят от текущей папки терминала.
Явно переданные относительные пути считаются от папки терминала.

Для новой версии корпуса задавайте новое имя каталога через `--out-dir`. Обучайте все сравниваемые
модели на одном manifest. Готовые запуски не перезаписываются. Для подключения нового запуска
к сайту обновите реестр `MODELS` и путь корпуса в `kazstyle/inference/service.py`;
совместимость модели и корпуса проверяется по хешу. Новые классы также требуют обновления
названий в сервисе и текста интерфейса. Это расширяемая структура, но пока интерфейс рассчитан на три класса.

При переносе 26.09.2026 содержимое корпусов и весов не менялось. Пути в старых provenance и
`source_snapshot` отражают структуру на момент обучения и намеренно сохранены. Старые записки
в `docs/research/2026-09-25/` могут содержать прежние команды; актуальные находятся в `WORKFLOW.md`.
