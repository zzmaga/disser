# Рабочие команды и хранение

Текущее состояние и очередь задач: [PROJECT.md](PROJECT.md). Инструкции GPU:
[GPU.md](GPU.md). Здесь команды и архитектура; история решений не дублируется.
Все команды выполняются из `D:\Disser`.

## Обновление страницы состояния

```powershell
.venv/Scripts/python.exe -m kazstyle.evaluation.project_status
```

Пересобирает `reports/PROJECT_STATUS.html` и `reports/ipm_progress_20261006.html`
из сохранённых результатов и актуальных пояснений в генераторе. Полный план хранится
в `docs/PROJECT.md`; при изменении этапов обновлять краткое представление в
`kazstyle/evaluation/project_status.py`. Числа кандидатов и календарь плана относятся
к указанной дате сверки, автоматически новым сбором не пересчитываются.
Команда не собирает данные, не обучает модели и не меняет профиль сайта.
Исторический `dissertation_audit_20261006/requirements.json` не является текущим статусом.

Английская рабочая рукопись собирается отдельно из сохранённых результатов:

```powershell
.venv/Scripts/python.exe manage.py thesis-english
```

Результат — `reports/dissertation_english/manuscript.html` и `evidence.json`.
Проза хранится в `kazstyle/evaluation/thesis_english.html`, таблицы формирует
одноимённый Python-модуль. Команда сверяет хеши корпуса и сохранённого разбиения,
не обучает модели. Это рабочий текст, а не завершённая диссертация по шаблону AITU.

## Переносимая демонстрация и CI

Пример очистки не требует корпуса, весов или GPU и не определяет стиль:

```powershell
.venv/Scripts/python.exe -m pip install -r configs/requirements-ci.txt
.venv/Scripts/python.exe -m kazstyle.demo --out-dir build/demo
.venv/Scripts/python.exe scripts/ci.py
```

Вход по умолчанию — пять искусственных записей `examples/cleaning_input.jsonl`.
Ожидается 3 сохранённых текста и 2 исключения. Для своего JSONL используйте `--input`;
схема каждой строки — только строковые `id,text`, ID непустой и уникальный.
Каталог результата должен быть новым. HTML, JSONL и сводка сохраняются вместе.

`scripts/ci.py` запускает 39 переносимых тестов очистки, хранения, демонстрации и HTTP API.
Расширенный вариант `scripts/ci.py --data` — 139 тестов, включая сборщики, экспорт,
дедупликацию и группировку. Для него установить `configs/requirements-data-ci.txt`.
Оба варианта не требуют корпуса, весов, PyTorch/Transformers или сети во время тестов.
Пропуски, ошибки и отсутствие обязательного тестового файла дают ненулевой код.
Полный набор с локальными весами запускается отдельно командой из предыдущего раздела.
`.github/workflows/ci.yml` выполняет проверки на Ubuntu и Windows, Python 3.12,
при push/PR в main или ручном запуске. Журналы и пример хранятся в Actions artifacts
14 дней; `build/` исключён из Git. Публикация сайта на хостинге не настроена.

## Данные: порядок следующей итерации

`configs/corpus_registry.json` указывает завершённый банк и незавершённые партии;
не считать `interrupted_checkpoint` завершённым сбором. Новая цель пользователя —

корпуса 10 октября. Публицистику не добирать; 2 000 — промежуточный этап.
Цель не является лимитом хранения полного банка.
В новом рецепте экспорта можно явно задать `collection_targets` для всех пяти стилей.
Прежние хешированные рецепты не редактировать.

```powershell

.venv/Scripts/python.exe manage.py export-corpus --help
.venv/Scripts/python.exe manage.py collect-poetry --help
.venv/Scripts/python.exe manage.py screen-legal --help
```

Проверка структуры CSV, длин и доли текста, попадающей в текущий вход моделей:

```powershell
.venv/Scripts/python.exe -m kazstyle.evaluation.document_lengths --corpus data/cleaned/unified_corpus_20261018b --dataset data/processed/text_only_v4_shared --out-dir reports/technical/dissertation_completion_20261018/curation_followup/lengths
```

Каталог результата должен быть новым. Этот уже содержит завершённую проверку;
для следующей версии выбрать другой путь. Команда только читает корпус и локальные
токенизаторы, не загружает веса и не обучает модели. Длины — слова, символы и токены
отдельно; CSV-записи и физические строки также считаются отдельно.

Ответы и комментарии из уже сохранённых страниц:
`.venv/Scripts/python.exe -m kazstyle.data.forum_replies --help`.
Параметр `--sources` принимает JSONL вопросов с `source_snapshot` и `source_sha256`;
`--out-dir` — новый каталог. Одна запись — полная пользовательская реплика, не кусок
вопроса. Вопрос и все ответы/комментарии сохраняют `parent_id` одной ветки; авторская
группа совместима со сборщиком вопросов. Результат требует содержательного просмотра,
при экспорте у такого входа обязательно `require_review: true`.

Удалять только воспроизводимые кэши, предварительно проверив абсолютный путь.
`data/`, `artifacts/`, `models/` и `archive/` не являются временными файлами.
Для `build/corpus_preview_20261010/` ранее зафиксирован запрет автоматического удаления;
обходить его другим инструментом нельзя. Это не актуальная версия корпуса.

1. Собирать **кандидатов**, сохраняя источник, исходный документ, способ отбора и дату.
2. Очистить, проверить язык, повторы и пригодность; причины исключения сохранить.
3. Проверить метки. Источник или ответ модели сам по себе не является экспертной меткой.
4. Объединить повторные публикации/фрагменты одного документа в группы до разбиения.
5. Построить новую версию корпуса: прежние CSV и завершённые выборки не переписывать.
6. Подготовить одинаковые фрагменты для сравниваемых токенизаторов. Сохранить manifest,
   метаданные и SHA-256; CSV для обучения — только `text,label`.
7. Сначала один проверочный запуск, затем полная серия после проверки данных.

Не уравнивать классы копированием строк. Ссылки хранить в метаданных, а из модельного
текста удалять. Не удалять автоматически все имена, даты и пунктуацию: это может
разрушить признаки стиля. Длинные/короткие тексты и жанры проверять отдельно.

Параметры конкретных этапов:

```powershell
.venv/Scripts/python.exe manage.py prepare-data --help
.venv/Scripts/python.exe manage.py apply-review --help
.venv/Scripts/python.exe manage.py build-clean --help
.venv/Scripts/python.exe manage.py build-shared --help
.venv/Scripts/python.exe manage.py audit-overlap --help
.venv/Scripts/python.exe manage.py prepare-views --help
.venv/Scripts/python.exe manage.py collect-business --help
.venv/Scripts/python.exe manage.py collect-university-forms --help
.venv/Scripts/python.exe manage.py apply-prose-metadata --help
```

`prepare-views` сохраняет точный фрагмент в границах всех токенизаторов указанного
эталонного корпуса. Разметка должна относиться к этому фрагменту, а не автоматически
распространяться на всю длинную публикацию. `audit-overlap` проверяет совпадающие
словесные фрагменты; его флаги разбираются до разбиения. При сборке учитываются
известные `author_group`, `work_group`, `template_family_id`; неизвестный автор не
объединяется с остальными неизвестными. Деловые шаблоны пока используются только в train.
`passage_group_id` консервативно объединяет совпадающие пятисловные фрагменты до
разбиения. Это не метка «дубликат»: цитаты и шаблоны тоже могут связывать документы.
После сборки выполняй `audit-overlap` на точных итоговых входах и проверяй пары между
частями; одного сравнения полного начала/конца документа недостаточно.
Для казахского вывода в PowerShell запускай Python с `-X utf8`.
При передаче не-ASCII кода через PowerShell here-string предварительно установи
`$OutputEncoding = [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()`.
Один `-X utf8` не восстанавливает символы, уже испорченные ASCII-конвейером PowerShell.

## Единый документный CSV (новая версия корпуса)

Основная версия: `data/cleaned/unified_corpus_20261018b/` (29 585 предварительных документов).
Рецепт этой версии: `configs/corpus_unified_20261018b.json`.
Команды ниже показывают историческую сборку 10 октября; старые рецепты сохраняются.
Проверять наличие `COMPLETE.json`; незавершённый каталог не использовать.

```powershell
.venv/Scripts/python.exe -X utf8 -m kazstyle.data.export_corpus --recipe configs/corpus_unified_20261010.json --out-dir data/cleaned/unified_corpus_20261010
.venv/Scripts/python.exe -X utf8 -m kazstyle.data.export_corpus --verify-dir data/cleaned/unified_corpus_20261010
```

Для повторной обработки нужен новый `--out-dir`. `--verify-dir` ничего не меняет.
Сборка 18 октября уже завершена; не запускать её повторно в существующий каталог:

```powershell
.venv/Scripts/python.exe manage.py export-corpus --verify-dir data/cleaned/unified_corpus_20261018b
```

Рецепт поддерживает восстановление `verified_folktale_vocabulary`: исторический текст,
снимок HTML, число кнопок и восстановленный текст должны совпасть с хешами решения.
Это восстановление слов источника, не генерация и не исправление стиля моделью.
Первоначальный экспорт 18 октября сохранён неизменным; дополнительный снимок нового
`folktales.py` — `reports/technical/dissertation_completion_20261018/source_addendum/`.
Сборка 18b и последующие экспорты включают модуль в каталог `code` автоматически.
Будущие экспорты также проверяют неизменность самого рецепта и файлов кода между
началом и сохранением результата; смешанный снимок не помечается завершённым.
Рецепт фиксирует SHA-256 входов, явные исключения и решения просмотра. Лимита
1000 документов на стиль здесь нет. Вопросы с форумов не принимаются по одному
названию сайта: новые кандидаты проходят отдельный просмотр.
`require_review_filters` также задерживает старые научные кандидаты
`bilim-all.kz / educational_article`: выборочный просмотр обнаружил планы уроков,
рекламу университета и личные эссе. Допуск конкретной записи требует решения,
привязанного к SHA текста. Просмотр помощником остаётся предварительным;
`reviewed_extent` различает весь текст и только заголовок, начало и конец.

- `corpus.csv` — все отобранные документы, ровно `text,label`.
- `by_style/*.csv` — те же записи отдельно по пяти стилям, тот же формат.
- `metadata.jsonl` — ID, источник, происхождение метки, SHA текста, группы;
  `corpus_row` — номер записи общего CSV с 1, без строки заголовка.
- `review.csv` — сомнительные подписи, адресоподобные токены, возможные контакты,
  ошибки извлечения. Флаг не означает, что текст обязательно плохой.
- `excluded.csv` и `audit.jsonl` — исключённые записи и объяснения решений.
- `corpus.html`, `summary.json`, `recipe.json`, `code/`, `COMPLETE.json` —
  описание, количества, воспроизводимость и контроль целостности одной версии.

CSV: UTF-8 с BOM, разделитель запятая, стандартное экранирование кавычек.
Стилевые метки: `Formal`, `Scientific`, `Publicist`, `Artistic`, `Colloquial`.
Имена, даты, нормальные знаки препинания и разная длина сохраняются; фрагменты
одного длинного произведения не считаются новыми документами.

Для программного чтения без второй полной копии текста:
`kazstyle.data.export_corpus.load_documents(path)` проверяет контрольные суммы
и собирает записи из CSV и метаданных. Для модели брать только поле `text`;
метки, адреса и группы нужны подготовке и оценке, а не признакам классификатора.
Это не готовый train/test: независимая проверка меток и аудит точных входных
фрагментов всё ещё нужны. Учитывать `split_group_id`, авторов и произведения.


## Проверка текстов и разметка

### Ревизия очистки перед новой сборкой корпуса

```powershell
.venv/Scripts/python.exe -X utf8 -m kazstyle.data.news_cleanup --input data/cleaned/expanded_v5_pool/candidates.jsonl --out-dir data/cleaned/source_cleanup_review_20261010
```

Этот каталог уже создан; для повторного запуска нужен новый путь. Модуль удаляет
подтверждённые элементы страниц Abai/BAQ по источнику и строгим шаблонам; стилевую
метку не использует. Общий очиститель сайта не изменён. `changes.jsonl` содержит
до/после и удалённые фрагменты; `review_queue.jsonl` — спорные подписи и таблицы.
Флаги не означают автоматическое исключение. Изменённые тексты требуют повторного
просмотра; перед обучением заново проверить точные входы и группы повторов.
Снимки обоих очистителей и хеши сохраняются в каталоге ревизии.
Это кандидаты, не готовый train/test. Старые v4/v6 и резервные источники не заменять.

Аудит и просмотр корпуса: `reports/corpus_audit_20261010/report.html` и `corpus.html`.

### Независимая проверка стиля

Пользователь выбрал AI-assisted curation. Текущий диагностический AI-аудит:
`data/annotation/corpus_pilot_20261018/`, 25 показанных текстов, решения в
`configs/reviews/corpus_pilot_20261018.json`. Это не независимая человеческая разметка,
не полная проверка корпуса и не новый финальный test. Фрагментный просмотр не означает
одобрение целого документа. Не подавать этот аудит напрямую как export-review.

Для слепого просмотра канонического корпуса без копирования всех текстов в JSONL:

Нужен новый `--out-dir`; 350 слов — прежний предел по умолчанию. Пакет фиксирует хеш

причиной и объёмом просмотра. Не заполнять от имени людей.

### Полные тексты из очереди, без повторного просмотра старых решений

`curate-pending` проверяет корпус и соответствие рецепта, затем отбирает только
ещё не одобренные записи с флагом семантического просмотра. Контактные, языковые
и другие технические флаги таким отбором не снимаются. Длинные тексты не обрезаются:
они не попадают в заданный диапазон. Источники — в отдельном manifest, показанный
пакет содержит полные оригинальные тексты и хеши. Решений программа не создаёт.

```powershell
.venv/Scripts/python.exe manage.py curate-pending --corpus data/cleaned/unified_corpus_20261018b --recipe configs/corpus_unified_20261018b.json --out-dir data/annotation/NEW_PENDING_PACKET --style colloquial --per-stratum 8 --min-words 56 --max-words 140 --seed 202610185
```

Для дополнительных партий до очередной сборки можно повторять `--prior-review`:
проверенные ID исключаются только при совпадении хеша исходного текста.
Решения: `configs/reviews/colloquial_curation_20261018_{1,2,3,4}.json`, 888 полных
текстов, 810 приняты по стилю. Все уже включены в рецепт 18b; повторно добавлять
эти review-файлы в него нельзя. Инструкция — `configs/style_annotation_guidelines.json`.
Она сформулирована после калибровочных партий; перед будущим reference её фиксировать.

### Канонический корпус → общий вход моделей

```powershell
.venv/Scripts/python.exe manage.py prepare-views --corpus data/cleaned/unified_corpus_20261018b --reference-dataset data/processed/tokenizer_reference_v7_20261018 --out-dir data/cleaned/NEW_SHARED_VIEWS --development-only
```

Пример использует закреплённые ограничения трёх encoder. `--development-only`
исключает зарегистрированные документы, полные группы и source units.
Без него резервные записи сохраняют статус `reserved` и не могут пройти сборщик
train. Пример не утверждает окончательные метки, не обучает и не назначает splits.
`corpus_split_group_id` сохраняет полную исходную группу при выборе фрагментов и
далее учитывается в `build-clean`, даже если связующий документ не выбран.
`text_sha256` относится к показанному фрагменту, `corpus_text_sha256` — к документу.
Изменение входов во время подготовки прерывает сборку без завершённого результата.

### Резерв и независимая фиксация токенизаторов

Существующие завершённые каталоги не пересоздавать. Для новой версии сначала
подготовить рецепт с COMPLETE-хешем корпуса, известными development-входами,
инструкцией разметки, source selectors, seed и бюджетом исключаемых групп.
Команда не сертифицирует метки и не регистрирует ledger автоматически:

```powershell
.venv/Scripts/python.exe manage.py reserve-evaluation --policy configs/reservation_v7_20261018c.json --out-dir data/annotation/NEW_RESERVATION --ledger configs/reservations/NEW_RESERVATION.json
.venv-gpu/Scripts/python.exe manage.py freeze-tokenizers --protocol configs/research_protocol_v7.json --out-dir data/processed/NEW_TOKENIZER_REFERENCE --allow-download
```

После проверки замыкания групп и размеров зарегистрировать путь и SHA-256 ledger
в `configs/evaluation_reservations.json`. Новый `build-clean` и оба trainer
проверяют реестр без отключающего флага. Проверка старых весов остаётся доступна.
`freeze-tokenizers` скачивает конфигурации и токенизаторы закреплённых ревизий,
не веса encoder; общий предел по умолчанию 256. Reference не является датасетом.
Резервные точные views готовятся отдельной командой `prepare-views --input`;
3 научных фрагмента первичной версии уже отдельно в `quarantine.jsonl`.

Если реальные независимые участники появятся, исторический диагностический пакет
`data/annotation/expanded_v6_audit_20261006/` содержит формы A и B для двух людей. Имя разметчика и его независимость программно не доказываются.
Сохранённые JSON кладутся отдельно от пустых шаблонов.

```powershell
.venv/Scripts/python.exe manage.py annotate compare --help
.venv/Scripts/python.exe manage.py annotate finalize --help
```

`compare` проверяет полноту и принадлежность ответов пакету, считает согласие и
создаёт шаблон разрешения разногласий. `finalize` требует согласования спорных случаев
и экспортирует только показанные человеку фрагменты, с исходными идентификаторами.
Это не автоматическое включение в train и не превращение аудита в новый внешний test.

### Следующее сравнение моделей

`configs/research_protocol_v7.json` — проект исследовательского протокола, **не**
исполняемый suite. Сначала зафиксировать корпус, группы, зарезервированные источники
и общий текстовый вход, затем создать отдельный план suite. Основные варианты:
три линейных pipeline, mBERT, Kaz-RoBERTa last и mmBERT-small после проверки памяти.
Новые модели пока не обучались. В планах suite разрешение сетевой загрузки задаётся
явным JSON boolean `allow_download` на уровне плана или модели; старое поведение
mBERT сохранено для воспроизводимости старых планов. Не включать загрузку весов
только ради диагностики сохранённых запусков.

## Возобновление сбора и фиксация новой версии

Форумный сборщик принимает `--resume`, `--max-seconds`, `--max-requests`.
Во время работы авторитетный файл — `CHECKPOINT.json`: в нём записи, очередь URL,
параметры и хеши кода. `candidates.jsonl` обновляется после штатной паузы/окончания.
Для мягкой остановки создать файл `STOP` внутри каталога конкретного сбора;
остановка произойдёт между запросами. Перед намеренным возобновлением незавершённого
сбора убрать только этот `STOP`; параметры, исключения и код должны совпадать.
Не возобновлять после 401/403/429 автоматически. Не запускать два процесса в один каталог.

**После включения партии в хешированный рецепт она неизменна.** `COMPLETE.json`
может фиксировать ограниченный снимок (`collection_finished: false`), а не полный
обход сайта. Дальнейший сбор тогда идёт в новый каталог, прежние URL исключаются.
Файл контрольной точки полезен для доказательства и не разрешает переписать такую партию.

Дополнительные команды (справка, без запуска нового обучения/сбора):

```powershell
.venv/Scripts/python.exe -m kazstyle.data.forum --help
.venv/Scripts/python.exe -m kazstyle.data.customer_reviews --help
.venv/Scripts/python.exe -m kazstyle.data.document_windows --help
.venv/Scripts/python.exe -m kazstyle.evaluation.window_probe --help
```

Отзывы KazSAnDRA берутся только из зафиксированного исходного train ZIP и исходного
поля `text`. Оценка тональности не является стилем. Поле
`requires_explicit_style_review` обязательно проверяется экспортёром, даже если автор
рецепта забыл `require_review`. Отсутствующие ID автора/товара не выдумывать.

Исправления мягких переносов прозы — `source_repairs` нового рецепта. Допускается
только удаление U+00AD между буквами после сверки HTML, старого извлечения и нового
SHA. Обычные пробелы и предполагаемые OCR-ошибки автоматически не склеивать.
Все решения просмотра привязаны к исходному тексту; полный просмотр и просмотр
заголовка/начала/конца имеют разные `reviewed_extent`.

JSON в `configs/` хранится в Git побайтно (`.gitattributes`). Завершённые рецепты и
решения не форматировать повторно: даже изменение переводов строк меняет SHA.
Новый каталог корпуса и новый рецепт обязательны при изменении очистки или решений.
Диагностика окон не меняет число документов, разбиение и профиль сайта.

## Обучение и сравнение

На новой версии корпуса классические модели переобучаются вместе с TF-IDF.
Для сопоставимых нейросетевых экспериментов берутся одинаковые исходные pretrained
encoder; продолжение старых весов записывается как отдельная процедура.

TF-IDF — способ представить текст числами, а LR и SVM — классификаторы этих чисел.
Поэтому «TF-IDF + SVM» является одной полноценной модельной цепочкой. В проекте три
независимые такие цепочки: словесный TF-IDF + LR, словесный TF-IDF + SVM и символьный
TF-IDF + SVM. У нейросетей собственный tokenizer и encoder, TF-IDF им не нужен.
Нейросеть дообучается для пяти классов с исходных предобученных весов; обучение
универсального языкового encoder с нуля на этом ноутбуке не выполняется.

План новой серии — `configs/experiment_expanded_v6.json`; журнал — `reports/expanded_v6/suite/`.
Статус завершения проверяй в `status.json`, не по наличию частичных весов.
Для следующей серии создаётся **новый** план с новым `run_prefix`, путём корпуса,
его хешем, seed, моделями и параметрами. Повторять старый план с прежними ID нельзя.

```powershell
.venv/Scripts/python.exe manage.py train-classical --help
.venv/Scripts/python.exe manage.py train-transformer --help
.venv/Scripts/python.exe manage.py train-suite --help
.venv/Scripts/python.exe manage.py summarize-seeds --help
.venv/Scripts/python.exe manage.py prepare-deployment --help
```

Выбор эпох/вариантов — по validation. Известный test сохраняет статус диагностического.
Полная серия включает все заранее заданные seed; не выбирать лучший seed по test.
GPU-настройки и проверка восстановления приведены в [GPU.md](GPU.md).

`train-suite --max-jobs 1` завершает одно задание и останавливается на безопасной границе.
`--resume` продолжает ту же серию, сверяя план, среду, исходный код и результаты уже
завершённых заданий. Во время серии не менять `kazstyle/*.py`. После аварийного
прерывания внутри задания автоматический перезапуск запрещён: причина сохраняется,
новый опыт получает новый ID. V5 намеренно прервана из-за обнаруженных пересечений.

`build-source-holdout` создаёт дополнительный диагностический набор по фиксированному
рецепту. Все группы, затрагивающие отложенный источник, исключаются из train/validation.
Модели начинают с исходных encoder; нельзя оценивать здесь уже обученные на v6 веса.
Это проверка изменения источника и жанра, а не независимый финальный test.

`build-training-views` — отдельный контроль длины train по фиксированному рецепту:
сохраняет документы, группы и метки, побайтно проверяет прежние validation/test;
при новом межчастевом совпадении отменяет сокращение соответствующего train-текста.
Выполненный `train_length_ablation_v1` не устранил нейросетевую ошибку заявления.

Для сравнения новых весов с основным сайтом без смены активного профиля:

```powershell
.venv/Scripts/python.exe manage.py serve --port 8766 --deployment configs/deployments/expanded_v6_shared.json
```

Основной порт 8765 и `configs/deployment.json` сохраняют v4. Веса экспериментального
профиля читаются через `artifact_path()` из архива. `evidence_path()` разрешает также
старые отчёты из `archive/reports/`; при двух копиях одного пути выдаёт ошибку.

## Отчёты и архив

- `reports/PROJECT_STATUS.html` — одна точка входа. Обновить: `manage.py project-status`.
- У нового эксперимента один каталог с ID; не делать копии с суффиксами final/final2.
- Логи и вспомогательные проверки — `reports/technical/`.
- `artifacts/` содержит активные модели; `archive/artifacts/` — остальные запуски.
- `artifact_path(run_id)` и `evidence_path(relative)` разрешают старые ссылки при чтении.
  Для нового обучения задаётся явный новый каталог в `artifacts/`.
- `results.json`, предсказания, параметры, manifest и снимок кода — доказательства.
  Завершённый запуск хранится целиком; внутренний snapshot не обновляется вместе с кодом.
- Из старой версии оставлять один отчёт/черновик в архиве, а не несколько «актуальных».
- Исторические инструкции в `archive/docs/` не являются текущим планом проекта.

Для освобождения места первыми можно рассматривать веса инженерных GPU-проверок и
прерванного v3-запуска. Сейчас они только архивированы. Повторы основной серии нужны
для воспроизводимости. Архив на том же диске не заменяет внешнюю резервную копию.
