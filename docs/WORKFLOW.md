# Классификация функционального стиля казахского текста

Рабочий этап: воспроизводимый пилот на **трёх стилях** — официально-деловом,
публицистическом и художественном. Старые эксперименты перенесены в
`archive/legacy_20260925/` и не используются новым кодом.

Корпус пока размечен по источникам, без подтверждённой ручной проверки. Каждый
класс происходит преимущественно из одного сайта. Высокие метрики этого пилота
не доказывают распознавание стиля на новых источниках и не подтверждают цифры статьи.

## Сайт для проверки своих текстов

Откройте **http://127.0.0.1:8765**. Для запуска после остановки сервера дважды
нажмите `start_site.cmd` или выполните:

```powershell
.venv/Scripts/python.exe manage.py serve --port 8765
```

Оставьте окно сервера открытым. Сайт работает локально. По умолчанию используется
Kaz-RoBERTa; можно выбрать другую модель или нажать «Сравнить все». Показанный ответ
действительно вычисляется сервером из сохранённых весов. Веса загружаются один раз
и затем переиспользуются. Тексты не записываются сервером и не отправляются во внешний API.

Сайт и CLI `predict` используют один сервис и разрешают короткие тексты с предупреждением.
Длинный ввод ограничивается одним центральным фрагментом, как при обучении.
Научный и разговорный стили пока не поддерживаются.

Кнопка «Скопировать результат» копирует исходный текст и ответы для разбора ошибок.
Это инструмент качественной проверки, а не замена фиксированному тесту. Числовая
«уверенность» не показывается, поскольку её калибровка не проверена.

Файлы: `kazstyle/api/server.py`, `kazstyle/inference/service.py`, `frontend/index.html`, `frontend/app.js`, `frontend/style.css`.

## Как модель читает CSV

Один CSV record — один документ с полем `text`. Длинная строка, запятые, кавычки
и переносы внутри корректно заключённого в кавычки поля допустимы. Физические
строки файла и документы — разные вещи. Новый загрузчик проверяет кодировку,
число полей и кавычки, отказывается молча пропускать повреждённые записи.

TF-IDF переводит текст в числовые признаки слов/символов; Logistic Regression
и LinearSVC обучаются по этим признакам. TF-IDF сам по себе не классификатор.
Для трансформера текст делится на subword-токены: 256 токенов не равно 256 словам.

В пилоте из каждого документа берётся один центральный фрагмент, не более 160
слов и 256 токенов сохранённого tokenizer Kaz-RoBERTa. Тот же текст получают все
модели. Длинные документы не получают больший вес за счёт сотен фрагментов.
Это эксперимент с фрагментами, а не проверка анализа всего длинного документа.

## Данные и разбиение

- Raw: `data/{official,publicistic,literary,scientific,colloquial}.csv` — не изменяются.
- Версия пилота: `data/processed/pilot_v2/`.
- По 300 документов на класс: 210 train / 45 validation / 45 test.
- Локальные ID пилота: Formal=0, Publicist=1, Artistic=2. Исходные глобальные ID
  сохраняются отдельно. Mapping всегда загружается из `config.json`.
- Точные совпадения и найденные семейства близких текстов группируются до split.
  Поиск близких текстов эвристический и не гарантирует обнаружение всех повторов.
- Баланс достигается отбором документов без размножения строк. Неиспользованные
  документы остаются в резерве; они не удаляются из исходников.
- `documents.jsonl` хранит полные тексты и происхождение, `manifest.jsonl` —
  конкретный ввод моделей, группы и split, `raw_audit.json` — проверку всех пяти CSV.
- `annotation_sample_train.jsonl` содержит 60 примеров для ручной проверки.
  Проверяйте исходный документ и анализируемый фрагмент; поля ручной разметки пустые.

## Запуск в PowerShell

Текущее окружение: `.venv/Scripts/python.exe`. Tokenizer и encoder первого
checkpoint доступны в локальном HF-кеше. Скрипты по умолчанию не скачивают модели.
Для нового окружения установите зависимости из `requirements.txt` и явно разрешите
скачивание через `--allow-download`. Новые каталоги результатов не перезаписываются.

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe manage.py build-data --out-dir data/processed/pilot_v2 --styles official publicistic literary --per-class 300
.venv/Scripts/python.exe manage.py audit-data --dataset data/processed/pilot_v2 --out-dir reports/data_audit_v2
.venv/Scripts/python.exe manage.py train-classical --dataset data/processed/pilot_v2 --out-dir artifacts/pilot_v2_classical
.venv/Scripts/python.exe manage.py train-transformer --dataset data/processed/pilot_v2 --out-dir artifacts/pilot_v2_roberta_last --head last --epochs 2 --batch-size 8 --threads 4
.venv/Scripts/python.exe manage.py train-transformer --dataset data/processed/pilot_v2 --out-dir artifacts/pilot_v2_roberta_concat4 --head concat4 --epochs 2 --batch-size 8 --threads 4
.venv/Scripts/python.exe manage.py compare --runs artifacts/pilot_v2_classical artifacts/pilot_v2_roberta_last artifacts/pilot_v2_roberta_concat4 --out-dir reports/pilot_v2
```

Если эти каталоги уже созданы, для повторного опыта укажите новые имена, например
`pilot_v3`, согласованно во всех командах. Не удаляйте старые результаты, чтобы
перезапустить команду. Другой seed для модели не означает новое разбиение:
разбиение закреплено в manifest.

## Что сохраняет обучение

Все классические варианты заданы заранее: Dummy, word TF-IDF + Logistic Regression,
word TF-IDF + LinearSVC и char TF-IDF + LinearSVC. TF-IDF обучается только на train.
Для трансформера сравниваются last-layer и concat4 на одном encoder и одном корпусе.
Лучшая эпоха выбирается по validation; test проверяется после обучения.

Каталог запуска содержит параметры, версии пакетов, хеш данных/кода, предсказания
по каждому примеру, F1 каждого класса, матрицу ошибок, веса и HTML-отчёт.
Для выполненных запусков сохранены копии исходников в `source_snapshot`, совпадение
с записанными хешами проверено. `configs/requirements-installed.txt` фиксирует фактические
версии окружения; для CPU-сборки PyTorch при переносе может понадобиться отдельный
индекс пакетов. Это снимок окружения, а не утверждение о проверенной установке на новой машине.
`manage.py compare` отказывается объединять результаты разных manifest.
`report.html` можно открыть обычным браузером; он автономный и не отправляет данные.

Стандартное отклонение между seed и внешняя проверка ещё не получены. Test уже
просмотренного пилота не следует многократно использовать для подбора новых решений.
После ручной разметки и расширения источников нужен новый заранее зафиксированный тест.

## Локальная демонстрация

```powershell
.venv/Scripts/python.exe manage.py predict --text-file example.txt
```

Проверка offline-загрузки checkpoint трансформера:

```powershell
.venv/Scripts/python.exe manage.py verify-model --run-dir artifacts/pilot_v2_roberta_last
.venv/Scripts/python.exe manage.py diagnose-data --out-dir reports/pilot_v2_diagnostics
```

По умолчанию загружается локальная Kaz-RoBERTa; `--model logreg` выбирает классическую модель. Это
трёхклассовый прототип. Научный и разговорный стили пока отсутствуют; неизвестный
стиль не может надёжно распознаваться этим closed-set классификатором. Тексты короче
40 слов классифицируются с предупреждением о недостаточном контексте. Некалиброванная вероятность
не выдаётся пользователю как уверенность. Загружать joblib следует только из доверенных
локальных запусков, поскольку формат допускает исполнение кода при десериализации.

Сайт вызывает тот же inference-код: текст → обработка → модель →
название стиля. Интерфейс является оболочкой; исследовательская часть — качество
корпуса, разметки, протокола сравнения и способность обобщать на новые источники.

## Дополнительный корпус Hugging Face

[MDBKD](https://huggingface.co/datasets/kz-transformers/multidomain-kazakh-dataset)
декларирует Apache-2.0 и предоставляет текст, предсказанный язык, признак казахских
символов и ID. Меток пяти функциональных стилей в нём нет. `kazakhBooks` не означает,
что каждый текст художественный; `kazakhNews` тоже требует проверки языка и содержания.
Границы оригинальных документов и их URL могут отсутствовать.

```powershell
.venv/Scripts/python.exe manage.py import-hf --source kazakhNews --limit 100 --max-mb 30 --out-dir data/external/mdbkd_news_candidates
```

Импорт закреплён на revision `7a1fcdf9830b1c34b44b3038aafb672447f41890`, ограничен по
объёму и числу записей, сохраняет происхождение и **пустые** style_label. При достижении
лимита байтов сохраняются только полностью прочитанные записи и причина остановки.
Это не случайная репрезентативная выборка и не готовое дополнение к train.
Kaz-RoBERTa предобучалась на MDBKD, поэтому его нельзя объявлять заведомо новым,
не виденным моделью внешним тестом. Для расширения нужны разметка, проверка повторов
и сохранение групп исходных документов.

2. Пересмотреть Colloquial и Scientific; для нового корпуса зафиксировать руководство

4. LLM API можно добавить как отдельный baseline: одинаковый фиксированный тест,
   заранее выбранный prompt, версия модели, стоимость, задержка и сохранённые ответы.
   Test-примеры нельзя использовать как few-shot подсказки. Использование внешнего
   API и платных запросов в текущем пилоте не выполняется.
