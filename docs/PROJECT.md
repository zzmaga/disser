# Паспорт проекта KazStyle

Обновлено: 2026-10-12. Это краткая постоянная память для владельца и новых агентов.
Подробные доказательства лежат по указанным путям; читать весь архив не требуется.

## Цель и границы

Тема из ИПМ: **«Построение корпуса и разработка системы определения текстового стиля
на казахском языке с использованием методов машинного обучения»**.
Пользователь хочет завершить работу примерно за месяц. Сейчас приоритет — качество
корпуса и подтверждённые эксперименты. Сайт уже служит инструментом проверки.
Пять классов: Formal, Scientific, Publicist, Artistic, Colloquial.
Генерация и перенос стиля (GAN/style transfer) не входят в основную задачу.

Новые 7 485 строк **не включены в корпус и не являются 7 485 проверенными документами**.

Исторический журнал завершил 500 кандидатов. Сохранённые контрольные точки целы;

Аудит: `reports/technical/project_audit_20261012/audit.json`. Проверены весь экспорт
14 164 документов, 2 986 исходных снимков новых партий, шесть весов по SHA профиля,
целостность и разделение известных групп в v4/v6. Повреждений не найдено.
Это структурная проверка, не прочтение каждого документа. Основные пробелы:

- 940 из 978 официальных текстов — законы; коротких заявлений и других деловых жанров мало.
- 668 из 681 научного текста — аннотации. Добавление журналов расширяет тематику,
  но не заменяет отдельную проверку учебного/объяснительного научного текста.
- Медианы длины: официальные 521, научные 166, новости 196, художественные 1 827,
  разговорные 23 слова. Нужны общие модельные фрагменты и оценка по длинам/жанрам.
- Источник тесно связан со стилем; экспертных меток и независимого финального test пока нет.
- `artifacts/` содержит четыре активных каталога; удаление сломает сайт. Архив хранит
  доказательства прежних опытов и не является резервной копией. Полный сайт пока требует
  локальных весов и токенизаторов; клонирование Git их не восстанавливает.
- Технический долг: сборщики используют разные форматы завершения и не все умеют
  безопасно продолжать прерванный сбор. Следующая доработка инфраструктуры — общий
  протокол контрольных точек/завершения, затем общий HTTP-клиент с сохранением исходников.
  Не объединять эти изменения с переобучением и не считать обычный checkpoint завершённой партией.

Исправления кода: форумная запись, исключённая по дате/качеству, больше не вытесняет
пригодную копию; сохранён список ранее исключённых ID для воспроизведения обработки.
Группировщик учитывает авторов/родительские документы схлопнутых копий. На текущем банке
дополнительных объединений не обнаружено; исправление защищает следующую версию.
Отбор `data/sampling.py` отделён от Transformers, пустые жанры больше не теряются.
HTTP API ограничивает ожидание тела запроса, проверяет его полноту и возвращает 503,
когда модель занята. API можно тестировать без нейросетевых зависимостей.
Экспорт поддерживает явные цели сбора и проверяемое удаление конкретных заголовков/подписей;
старый экспорт и результаты не изменены. Нового обучения не было.

Проверки исправлений: 124 локальных теста, 76 изолированных CI-тестов, 28 минимальных;
все без ошибок и пропусков. Изолированный CI использует установленный Python 3.14;
Результат Ubuntu/Python 3.12 проверяется отдельно в GitHub Actions для конкретного коммита;
локальный прогон сам по себе его не подтверждает.
Сохранность 26 файлов корпуса/выборок/весов/профиля подтверждена SHA, 20 локальных ссылок
сводной страницы существуют. Визуальная проверка браузером в этот аудит не входила.
Уборка: проверены 8 каталогов `__pycache__` в коде/тестах (105 файлов, около 1 МБ).
Их удаление через PowerShell отклонено автоматической проверкой: `blocked by policy`,
без подробной причины. Файлы не удалены, обход не предпринимался; реестр и результат —
`reports/technical/project_audit_20261012/cache_cleanup_{manifest,result}.json`.

Следующий шаг: завершить содержательный отбор новых партий, собрать недостающие
разговорные/художественные документы с разнообразием источников, построить новый
корпус по хешированному рецепту и выделить сбалансированный набор без копирования строк.
Не выдавать увеличение числа кандидатов за достижение цели 2 000 качественных текстов.
