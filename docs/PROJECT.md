## Цель и решение на сегодня

Точная тема: **Corpus Construction and Development of a Text Style Identification
System for the Kazakh Language Using Machine Learning Methods**. Пять классов:
Formal, Scientific, Publicist, Artistic, Colloquial.

Основу работы уже можно писать. Готовность к защите пока не подтверждена: нужны
зафиксированная итоговая выборка, прозрачные метки, оценка на резервных группах,
окончательный английский текст, требования допуска и публикационный статус.
Новизна — проверяемое построение корпуса и исследование переносимости стиля,
а не обязательная новая архитектура и не обещание конкретного F1.

**Следующая задача:** AI-assisted проверка оставшихся **947 точных резервных views**,
разбор 7 замечаний пилота и 3 языковых карантинов. Затем — зафиксировать фактический
reference, общий train/validation и выполнить одну сравнительную серию v7.
Аудит пересечений уже завершён: после расширения эмбарго **0 флагов** между
резервом и актуальными development-views по заданным порогам. Совместимость
mmBERT-small с CUDA и архитектуры ModernBERT с CPU проверена. Итоговых метрик v7 ещё нет.
Промежуточный ориентир **2 000 документов каждого стиля достигнут**. Дальнейший
добор — ради разнообразия: длинные разговорные сообщения, деловые тексты вне законов,
научно-объяснительная проза. Не ждать бесконечно 11 425/стиль и не обучать заново ради числа.

## Модели и пределы результатов

Сайт работает локально без внешнего ИИ API: `start_site.cmd`, порт 8765.
Стабильный профиль v4: 610 фрагментов, train 370 / validation 120 / test 120.
Шесть вариантов: word TF-IDF + LR, word TF-IDF + SVM, char TF-IDF + SVM,
mBERT, Kaz-RoBERTa last, Kaz-RoBERTa concat4. Все исследовались с seed 42/43/44.
TF-IDF — признаки, LR/SVM — классификатор; это законченные модели.

Расширенная v6: 1 265 фрагментов (980/140/145), по 253/стиль. Основная модель
по среднему validation — Kaz-RoBERTa last. Средний внутренний test Macro-F1
0,9724; у стабильного v4 — 0,9443. Test уже изучались, метки предварительные.
Это не качество на любом казахском тексте. Отдельный source-holdout даёт 0,8985
для Kaz-RoBERTa, но использует другой train и другой test; разность не является
чистой оценкой влияния источника. `reports/expanded_v6/` содержит доказательства.

V6 не заменяет сайт: знакомое школьное заявление у Kaz-RoBERTa v6 стало Colloquial.
Фотосинтез распознаётся Scientific. Не обучать на знакомых проверочных примерах
незаметно и не менять выбор модели по их test-ответам. Историческая v5 остановлена
из-за пересечения юридических фрагментов; её нельзя включать в сравнение как чистую.

Лемматизация Stanza KTB уже проверялась: устойчивого улучшения не получено.
Отрицательный результат удовлетворяет исследовательской проверке метода;
не добавлять бесконечные повторы ради улучшения числа.

## Как обновить методы без смены темы

Обязательная основа следующего сравнения: три линейных модели, mBERT,
Kaz-RoBERTa last и кандидат **jhu-clsp/mmBERT-small** (140M, многоязычный
encoder; карточка и API содержат kaz). Ревизия кандидата:
`abc32620dd4f6ab06f5fbe905dc25f310618e09f`. Предобученные веса загружены;
токенизатор и память проверены, выполнены три технических шага оптимизации без
сохранения весов. Полноценное обучение классификатора и оценка v7 ещё впереди.
Обычный ModernBERT-base ориентирован на английский/код; новизна названия не
обосновывает его выбор для казахского. XLM-R и одна локальная LLM — дополнительные
варианты после основного результата, если отвечают отдельной гипотезе.

Проверка выбора методов 19 октября: `training/classical.py` использует готовые
`TfidfVectorizer`, `LogisticRegression` и `LinearSVC` из scikit-learn;
`models/style_transformer.py` — `AutoModel.from_pretrained` и линейную голову PyTorch.
Шесть текущих вариантов не являются шестью разными алгоритмами: word/char SVM
и last/concat4 — сравнения представлений. CatBoost/XGBoost пока не реализованы.
Рекомендация перед фиксацией v7: рассмотреть один CatBoost с готовой обработкой
текста как дополнительное сравнение с бустингом; преимущество не установлено.
Это предложение, не изменение списка моделей протокола и не выполненное обучение.
У линейных baseline сейчас фиксирован `C=1`; небольшой заранее ограниченный подбор
по validation возможен после фиксации development-разбиения, без доступа к test.
Главный незакрытый переход — от старых 370/980 обучающих фрагментов v4/v6 к новому
проверенному корпусу. Смена названия алгоритма не устраняет перекос жанров и меток.
Основание для кандидата: https://catboost.ai/docs/en/concepts/algorithm-main-stages_text-to-numeric .

Адресный аудит кода до упрощения: 82 Python-файла, 8 890 физических строк,
из них data — 5 692, evaluation — 1 887, training — 506; диспетчер показывал 51 команду.
Готовые NumPy/Pandas/sklearn/PyTorch/Transformers импортируются и установлены в `.venv`.
Проблема навигации и избыточной обвязки подтверждена; это не отсутствие библиотек.
По следующему прямому запросу пользователя **миграция сервера выполнена**:
`api/server.py` использует FastAPI/Pydantic/Uvicorn; старый `handler_for` и ручное
управление сокетами удалены. Адрес сайта, API, выбор модели и активные веса сохранены;
схема `/openapi.json` доступна без CDN. Параметры запуска — прежние `manage.py serve`.
Генерация общего отчёта и английской рукописи использует Jinja2 (`rendering.py`,
`templates/`); исходные числовые результаты не меняются. Удалены старый русский
`evaluation/manuscript.py`, `manuscript_expanded.html` и команда `build-manuscript`:
осталась актуальная `thesis-english`, прежние результаты доступны через историю.
Самописный `scripts/ci.py` уже отсутствовал; его ссылки заменены стандартным pytest,
набор переносимых проверок — `pytest.ini`, формат журнала — JUnit XML.
Ручной цикл PyTorch пока сохранён; Trainer — отдельная возможная миграция следующего
обучения, а не выполненная работа. Не подменять этим проверку корпуса и не менять

Видеокарта RTX 3050 Laptop 4 ГБ. `.venv` — сайт/CPU, `.venv-gpu` — обучение.

## Публикационная стратегия

Сначала одна содержательная статья: **Source-Aware Corpus Construction and Functional
Style Identification for Kazakh**. Вклад: новая прослеживаемая версия данных,
ошибки извлечения/меток, контролируемое сравнение и перенос между источниками.
Явно отделить расширение от прежней конференционной работы, сослаться на неё
после подтверждения выходных данных. Не размножать одну работу по нескольким журналам
одновременно; резервный журнал — после отказа/отзыва предыдущей подачи.

Обязательность именно Scopus для допуска пока **не подтверждена**. Публичная
методичка AITU, ДП-AITU-19, п. 4, указывает публикацию и/или выступление;
Scopus в требованиях к научному руководителю не переносится на магистранта.
Полный актуальный документ для набора 2025 получить не удалось: Moodle недоступен,
есть индексируемые выдержки. Нужно подтверждение Офиса послевузовского образования.
ИПМ содержит план трёх публикаций; план не является доказательством нормы закона.
IEEE PDF и сообщение о принятии не заменяют DOI/письмо/запись в proceedings.

Рассматривать сначала тематический журнал по NLP/корпусам после проверки scope,
индексации и правил продолжения конференционной статьи. IEEE Access — возможный
платный вариант; опубликованные сроки не гарантируют конкретное принятие.
Scientific Journal of AITU — вариант только при подтверждении требований кафедры;
его Scopus-статус здесь не установлен. Ничего не отправлено и не оплачено.
