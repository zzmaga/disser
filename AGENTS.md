# KazStyle: точка входа для агента

Рабочий проект магистерской диссертации. Пользователь хочет готовую исследовательскую
работу и понятный код, а не бесконечные повторные обучения и планы.

## Начало работы

1. Прочитай `docs/PROJECT.md`: актуальное состояние, решения, ограничения, следующие задачи.
2. Открой только нужный раздел `docs/WORKFLOW.md`; для GPU — `docs/GPU.md`.
3. Проверь `git status --short` и файлы, относящиеся к текущему запросу.
   В проекте могут быть незакоммиченные изменения предыдущих сессий — сохраняй их.

Не сканируй весь проект и не читай все отчёты, корпуса и снимки кода для восстановления
контекста. `artifacts/`, `models/`, `data/`, `.venv*/` и
`reports/technical/` открывай адресно, когда задача требует конкретного доказательства.
Сводная страница для человека: `reports/PROJECT_STATUS.html`.
Карта модулей и следующий шаг — в `docs/PROJECT.md`. Диссертация сдаётся на английском;
рабочая рукопись — `reports/dissertation_english/manuscript.html`.

## Инварианты исследования

- Действующий профиль — `configs/deployment.json`. Сайт работает локально, без ИИ API.
- Ссылки нужны в метаданных для происхождения и группировки; классификатор получает текст.
- Исходные CSV и завершённые версии корпуса/экспериментов сохраняй, если пользователь
  явно не поручил их удалить. 19.10.2026 пользователь поручил убрать весь `archive/`:
  история — `docs/EXPERIMENTS.md`, компактные доказательства без весов —
  `reports/experiment_history/evidence.zip`. Не восстанавливай старые веса без запроса.
  Новая обработка —
  новая версия и новый каталог. Не подменяй старые метрики более удобными результатами.
- Разделяй предварительные метки, человеческую разметку и ответы моделей.
  Не называй автоматически собранный набор экспертным или окончательным test.
- Пользователь поручил проверку ассистенту: сохраняй её как AI-assisted curation,
  с хешем показанного текста, причиной и объёмом просмотра. Не выдумывай ответы людей.
- Не смешивай документы/группы повторов между train, validation, test. TF-IDF fit — только train.
- Выбирай модели/эпохи по validation; ранее изученный test остаётся диагностическим.
- Готовый encoder дообучается; название Kaz-RoBERTa не заменяется названием KazBERT.
- Для чтения сохранённых запусков используй `artifact_path()` / `evidence_path()`
  из `kazstyle/settings.py`: прежние результаты извлекаются из проверенного ZIP
  в удаляемый кэш `build/experiment_evidence/`; веса снятых с хранения моделей отсутствуют.
  Эти функции не предназначены для выбора каталога нового обучения.
- Не запускай обучение только ради очередного числа. Сначала проверь изменения данных,
  затем один проверочный запуск; полную серию выполняй по зафиксированному плану.

## Память и порядок после работы

При существенном результате обнови `docs/PROJECT.md`: факты, доказательство, оставшиеся
задачи и краткую запись в истории решений. Команды меняй в `docs/WORKFLOW.md`,
GPU-инструкции — в `docs/GPU.md`. Не создавай очередной STATUS/PLAN/TODO/FINAL рядом.
Логи и проверки среды помещай в `reports/technical/`, отчёт эксперимента — в один
каталог с понятным ID. Полные веса, предсказания и исходники эксперимента храни вместе.
Не создавай заново папку `archive/`. Итоги завершённых опытов добавляй в
`docs/EXPERIMENTS.md`; новые полноценные эксперименты сохраняй вместе до отдельного решения об удалении.
Проверяй изменения по существу: сайт, восстановление весов и сохранность результатов.
