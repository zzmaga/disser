# Устройство проекта

`manage.py` и `python -m kazstyle` запускают одинаковые команды. Список: `python manage.py --help`.
Параметры команды: `python manage.py train-transformer --help`.

| Папка | Назначение |
| --- | --- |
| `kazstyle/api/` | Локальный HTTP-сервер и маршруты сайта |
| `kazstyle/inference/` | Загрузка сохранённых весов, предсказания, CLI |
| `kazstyle/models/` | Архитектура нейросети |
| `kazstyle/training/` | Обучение классических моделей и трансформера |
| `kazstyle/data/` | Чтение CSV, очистка, фрагменты, split, аудит, импорт кандидатов |
| `kazstyle/evaluation/` | Метрики, отчёты, сравнение и проверка весов |
| `frontend/` | HTML, CSS и JavaScript интерфейса |
| `configs/` | Версии источников, решения проверки, профили моделей и окружение |
| `data/` | Исходные CSV; `processed/` — версии корпуса; `external/` — кандидаты |
| `artifacts/` | Отдельная папка каждого запуска обучения и его веса |
| `reports/` | Сгенерированные отчёты |
| `docs/research/` | Материалы и выводы исследования с датой |
| `tests/` | Проверки данных и локального предсказания |
| `archive/` | Старый код, эксперименты и временные материалы |

Поток запроса: браузер → `/api/classify` → `InferenceService` → подготовка фрагмента → локальная модель → стиль.
CLI `predict` использует тот же сервис. Внешний ИИ API не вызывается.
`kazstyle/settings.py` задаёт корень проекта; пути по умолчанию не зависят от текущей папки терминала.
Явно переданные относительные пути считаются от папки терминала.

Для новой версии корпуса задавайте новое имя каталога через `--out-dir`. Обучайте все сравниваемые
модели на одном manifest. Готовые запуски не перезаписываются. Для подключения нового запуска
к сайту используйте JSON-профиль в `configs/deployments/`: путь корпуса, список запусков,
тип и файл каждой модели. Активный профиль — `configs/deployment.json`.
Альтернативный профиль: `manage.py serve --deployment configs/deployments/text_only_v3.json`.
Совместимость модели и корпуса проверяется по хешу; сайт получает список классов из сервера.

Обработка данных: `download-data` / `collect-data` → `import-sources` → `apply-review` →
`prepare-data` → `build-clean`. В версии `text_only_v3` CSV содержат только `text,label`;
URL, группы документов и происхождение хранятся отдельно в `metadata.jsonl`.
Перед обучением CSV сверяются с контрольными суммами и отчётным manifest.
`quality.py` задаёт одинаковую очистку для сборки корпуса и запросов сайта.

При переносе 26.09.2026 содержимое корпусов и весов не менялось. Пути в старых provenance и
`source_snapshot` отражают структуру на момент обучения и намеренно сохранены. Старые записки
в `docs/research/2026-09-25/` могут содержать прежние команды; актуальные находятся в `WORKFLOW.md`.


В сравнении с mBERT модуль `models/tokenization.py` регистрирует несколько
локальных токенизаторов и подбирает одну общую строку под их ограничения.
`data/shared.py` создаёт производную версию корпуса с теми же документами и split.
`training/suite.py` исполняет заранее заданные конфигурации и seed;
`evaluation/repeated.py` пересчитывает сохранённые метрики, агрегирует все запуски
и оценивает условную неопределённость bootstrap. `inference/deployment.py`
формирует профиль только после завершения серии и проверки весов.

Контур разметки: `annotate build` → два независимых ответа → `annotate compare`
→ согласование расхождений человеком → `annotate finalize`. Последняя команда
проверяет связь с исходными данными и экспортирует только прочитанные фрагменты,
не изменяя активный корпус. `annotation.py` отвечает за слепые формы и согласие,
`adjudication.py` — за согласованные решения и происхождение. Личность людей
и лингвистическая правильность решений не устанавливаются программно.

`evaluation/linear_audit.py` объясняет аддитивные оценки линейных моделей;
`evaluation/diagnostics.py` проверяет известные примеры и изменения имён/дат;
`evaluation/external.py` отдельно отмечает повторную проверку уже просмотренных
веб-примеров. Результаты этих проверок не дописываются в обучающие CSV.

`data/morphology.py` применяет фиксированные локальные модели Stanza к тем же
фрагментам и сохраняет леммы, POS, морфологические признаки и связь с исходным
текстом по хешу. `evaluation/morphology.py` сравнивает raw / stanza_surface /
stanza_lemma с одинаковыми линейными классификаторами. Этот дополнительный опыт
изолирован от реестра шести моделей сайта.

`training/gpu_check.py` проверяет память и успешность обновлений на train;
`training/transformer.py` поддерживает CPU float32 и CUDA mixed precision,
gradient checkpointing и fused AdamW. Окружения и команды: `docs/GPU.md`.
`evaluation/figures.py`, `manuscript.py`, `project_status.py` собирают рисунки,
рабочую рукопись и навигацию по подтверждённым результатам.
